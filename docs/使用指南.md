# ADHD Focus Guard 使用指南

这份指南按“第一次使用—每天怎么用—数据怎么管理”的顺序编写。最简单的用法是保持 ActivityWatch 和 ADHD Focus Guard 在后台运行，早上填写今日目标，其余记录由系统自动完成。

## 1. 第一次使用

先安装并启动 ActivityWatch。确认浏览器能打开 `http://127.0.0.1:5600`，并且时间线中已经出现窗口活动；如果希望记录浏览器域名，还需启用 ActivityWatch 的浏览器扩展。

然后启动 ADHD Focus Guard。软件不会再显示传统主窗口，而是自动在默认浏览器中打开本地工作台；后台托盘、截图、提醒和全屏遮罩仍由 Windows 程序负责。打开“设置”，填写以下内容：

- Base URL：DeepSeek 默认是 `https://api.deepseek.com`
- API Key：你自己申请的密钥
- 文本模型：默认 `deepseek-v4-flash`
- 视觉模型：默认 `deepseek-v4-flash-vision-exp`

点击“保存并测试”。连接测试使用程序自己生成的测试图片，不会截取真实桌面。视觉实验模型的名称或开放权限可能随服务商变化；如果测试失败，请以 DeepSeek 控制台显示的可用模型名为准。

API Key 只以 Windows 当前账户可解密的形式保存在本机。不要把配置目录、密钥或包含私人数据的导出包上传到公开仓库。

## 2. 每天开始时

系统以早上 8 点作为一天的边界。当天检测到你实际开始使用电脑约 2 分钟后，会弹出今日计划窗口。你可以一次写下多件想做的事，也可以参考 AI 根据仍处于进行中的长期、阶段和本周目标给出的建议。

提交后不会直接保存。AI 会先把原文拆成最多 5 个可验证的今日目标，为每项补充完成标准、优先级、预计时间和归类依据，并尝试关联到已有的长期、阶段或本周目标。预览中的每一项都能修改标题、完成标准、优先级、预计时间和关联目标，也能单独删除；确认按钮会按剩余条数更新。只有最后确认的项目才会写入，全部取消或 AI 请求失败时不会保存。浏览器“目标”页中的今日计划入口使用相同流程。

目标可以随时修改，所以今日建议只是一份当时的参考，不会锁定后续安排。暂时不想填写时可以延后 10、30 或 60 分钟；关闭当天提示后不会反复打扰。

## 3. 目标怎么管理

“目标”页支持长期、中期、短期和今日四种时间尺度。创建时只需填写标题，也可以补充说明、截止时间和一个较弱的上级目标关联。

目标状态包括进行中、已完成、暂停和放弃。已完成、暂停或放弃的目标不会发送给 AI，但记录和状态变更历史仍保留；重新恢复为进行中后，它会再次进入 AI 的上下文。

目标卡片提供“修改”和“删除”。修改时可以调整标题、完成标准、时间尺度、状态、优先级、预计时间、截止日期和关联目标；系统会保存变更历史。删除是不可撤销的永久删除，会同时清理这条目标的变更历史以及其它目标、事务和记忆对它的关联。一般更推荐将目标设为完成、暂停或放弃，以便以后复盘。

## 4. 随手写事务

“事务收集箱”用于手动打开软件后快速输入一段没有整理过的话，例如“周五前完成课程报告，明晚先找三篇参考文献”。

点“AI 整理”后，系统会把内容拆成待办事项并尝试关联到现有目标。此时只是预览，你可以修改标题、日期和关联目标，也可以删掉不合适的候选。只有点击确认后，事务才会正式保存。

这一步始终保留人工确认，避免 AI 误解一句话后直接改变你的计划。

## 5. 记忆页

“记忆”页保存适合长期回看的分条信息，例如个人偏好、有效方法、重要约束和项目背景。你可以手动新增、编辑、置顶、归档和删除。

AI 在周报或月报中发现值得保留的规律时，也可以生成记忆候选。AI 写入的内容默认是“待确认”，只有你确认后才成为正式记忆。搜索会在标题、内容和标签中匹配。

## 6. 自动活动记录如何工作

程序每隔约 5 秒读取一次本机 ActivityWatch，不会把 ActivityWatch 的完整原始数据库复制过来。它主要读取前台程序、窗口标题、浏览器域名和 AFK 状态，然后合并成连续活动片段。

活动最终只使用三类：

- 学习与工作：课程、阅读、写作、编程、项目和学校事务等有明确产出的活动
- 娱乐：视频、游戏、社交媒体和其它以消遣为主的活动
- 其它：目前无法可靠判断，或不适合放进前两类的活动

离开电脑是观察状态，不是第四个活动类别。ActivityWatch 的 AFK watcher 根据键盘和鼠标最后一次输入时间判断你是否在电脑前。因此只把网页打开却没有任何输入，超过 ActivityWatch 的空闲阈值后会被标记为 AFK；程序暂停视觉识别，也不会把这段时间误算成你一直在看该网页。它无法知道你是否在不碰键鼠地认真看纸质资料或长视频，所以仍允许手动纠正。

已知程序、域名和你纠正过的规则优先在本地分类。低置信度的新活动会先积累，系统约每 15 分钟把最多 50 个不同的活动摘要放在一次文本请求中批量分类，以降低费用。不会发送截图给文本分类模型。

## 7. 手动纠正与规则记忆

在活动页选中错误记录后，可以改成正确类别，并选择规则范围。范围越窄越安全：只记当前标题适合特定页面；按域名适合同一网站；按应用适合同一程序；全局关键词适合稳定且明确的命名。

系统保存的是匹配规则，不是训练一个新模型。以后出现相同应用、域名或相似标题时，本地分类器会先应用你的规则，优先级高于 AI 自动缓存。你还可以选择是否把纠正回填到已有的相似历史记录。

活动重叠时，程序会让你选择替换原记录或只填补空白，避免无提示地重复计时。很短且无法确认的片段归为“其它”，不会强行猜测。

## 8. 什么时候会截图和调用视觉 AI

视觉识别不是全天逐帧运行。只有 ActivityWatch 判断你处于活动状态，而且本地活动分类持续进入“学习与工作”约 30 秒后，自动视觉监控才会启用。离开电脑或持续进入其它类别约 120 秒后会退出。

启用后每 5 秒观察一次，但不会每次都请求 AI。程序先计算 256 位 dHash；首次观察、画面变化的汉明距离达到 30，或距上次 AI 判断达到 30 秒时才发请求。任何时刻最多一个请求，忙碌期间只保留最新一帧，所以网络变慢不会形成越来越长的请求队列。

模型根据当前目标、前台活动和屏幕判断三种状态：专注、轻微走神、明确分心。轻微走神表示当前活动可能偏离目标但证据不强；明确分心表示屏幕内容和目标明显无关。AI 无法观察时使用单独的 unavailable 状态，不会混入你的专注统计。

截图仅取主显示器，缩放到最长边 1660，JPEG 质量约 70%，只存在内存。程序自己的主窗口、顶部提示和遮罩会尽力通过 Windows 截屏排除接口隐藏；如果排除设置失败，自动视觉监控不会启动。

## 9. 提醒规则

保持专注时不提醒。连续轻微走神约 120 秒后显示一次顶部胶囊，之后仍未恢复时最多每 60 秒轻提醒。

首次明确分心会立即显示顶部胶囊、托盘通知并播放声音。明确分心持续约 30 秒，并且至少得到两次独立 AI 判断后，会显示一次 15 秒全屏半透明遮罩。同一连续分心区间只出现一次强提醒，之后最多每 60 秒轻提醒。

遮罩中的“AI 误判，本段不再提醒”会让当前分心区间静音，直到 AI 明确判断已经离开分心状态。这样不会因为同一个误判持续打断你。

处于自动学习与工作状态后又连续娱乐时，会在约 2 分钟和 5 分钟各轻提醒一次，不无限重复轰炸。

## 10. 手动专注计时

“专注”页保留一个独立的手动工具。输入本轮目标，选择 15、25、45、60 分钟或自定义 1–300 分钟后开始。它会显示剩余时间和状态，结束时生成本轮复盘。

手动会话运行时，自动视觉监控不会再开第二套并行截图判断。停止或到期后的迟到 AI 结果会被丢弃。睡眠和锁屏不暂停倒计时，无法观察的时间记为未知。

新版没有休息计时，也没有“休息”分类。

## 11. 报告与统计

“总览”页可以切换今天、3 天、7 天、14 天和 30 天。顶部数字卡片快速显示学习与工作、娱乐、每日平均记录和目标数量；下方同时提供每日分类堆叠图、类别占比环图、一天中各小时的活跃节律、活动排行和最近时间线。报告页支持日报、周报和月报，内容包括分类时长、主要活动、目标上下文和客观总结。

日报按早上 8 点到次日 8 点计算；周报和月报基于已经保存的活动和目标生成。AI 暂时不可用时，系统仍会生成本地模板报告，后续周期再重试，不会因为断网停止记录。

报告中的数据是行为证据，不等于价值判断。打开某个页面只能说明它处于前台；AFK、手动纠正和视觉判断共同降低误差，但不能完全理解现实世界中的所有行为。

## 12. 每日 AI 预算

默认每日软预算是 1 元，同样以早上 8 点重置。系统依据模型返回的输入、缓存和输出 token 估算费用；实验视觉模型的实际价格如果与文本模型不同，控制台账单应当作为最终依据。

达到预算时会弹窗询问。选择暂停后，自动视觉和非必要活动分类、报告润色会停止，但 ActivityWatch 本地记录、目标、事务、记忆和手动操作继续工作；选择继续则允许当天继续调用。预算不是支付平台的硬限额，真正的费用控制还应在 API 服务商控制台设置。

## 13. 数据、备份和删除

普通设置和加密密钥位于 `%LocalAppData%\Vigil`。会话、目标、活动、事务、记忆和报告使用 SQLite 保存，其中敏感文本字段以 Windows DPAPI CurrentUser 保护。同一个 Windows 用户可以读取，换账户或换电脑不能直接解密。

设置页可以导出 ZIP。导出包含结构化 JSON、活动 CSV 和报告 Markdown，不包含 API Key、截图、日志或 ActivityWatch 原始数据库。ZIP 本身没有加密，建议放在可信位置。恢复前最好先另做一次导出；导入会把包内数据写回当前资料库。

可以删除单条历史、删除当天活动，或清空新版个人数据。删除不可撤销，清空前请先备份。程序不会在 `%LocalAppData%\Vigil` 中保存屏幕截图。

## 14. 托盘、快捷键与退出

关闭浏览器标签页不会停止软件，后台记录仍继续。托盘菜单可以重新打开浏览器工作台、停止当前手动会话或彻底退出。全局快捷键 `Ctrl+Alt+Shift+Space` 用于快速打开工作台。

若要完全停止 ActivityWatch 读取和后台记录，请从托盘选择退出，而不是只关闭浏览器标签页。

## 15. 常见问题

看不到活动时，先确认 ActivityWatch 正在运行且 `http://127.0.0.1:5600` 可以打开；再检查窗口 watcher 和 AFK watcher 是否已有事件。浏览器只有窗口标题、没有域名时，通常是浏览器扩展未安装或未连接。

连接测试失败时，依次检查 Base URL 必须为 HTTPS、模型名是否在账号中可用、余额和权限、系统代理以及防火墙。401 通常是密钥或权限问题，429 通常是限流或余额问题，超时和 5xx 会降级重试，不会中断本地计时。

视觉一直未启动时，确认当前活动已被分类为学习与工作、你没有处于 AFK、当天预算未暂停，而且 Windows 截屏排除设置成功。也可以先在活动页纠正当前应用，帮助系统以后自动识别。

如果分类不符合你的真实意图，优先使用手动纠正并选择尽可能窄的规则。系统的目标是可解释和可改正，不是假装自动判断永远正确。
